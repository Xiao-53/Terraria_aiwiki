- 当前 Search 按规范页面合并后应用上限，保留 `EvidenceRegions`，单概念标题候选优先；加工器使用真实自身/祖先 Anchor，并为新页面站内链接写入 `data-wiki`。更新后必须保持这些已修复行为。

## 目标与完成定义

1. 日常更新优先读取上次成功同步以来的远端变更，合并同页多次变化后只下载必要页面和媒体。
2. 新建、编辑、删除、移动及 Redirect 转换能够收敛到远端当前可见状态；模板和文件依赖不得被静默忽略。
3. 普通小批量更新不抓取全部页面/Redirect 列表，不逐页读取本地 HTML，不重建全库索引。
4. 无有效同步进度或无法证明日志覆盖时，执行完整目录核对；只替换变化内容，不要求重下现有数据库。
5. 取消、断网、解析失败、事务失败及重启均不越过未完成变化；已提交页面始终可搜索和阅读。
6. Windows 自动化、临时数据库故障注入和真实只读 API/副本更新验收通过，记录请求数、下载字节数及耗时，才可标记 completed。

## P0 / 兼容性影响

- 每页仍使用原子事务更新 HTML、章节、区域和 FTS。受模板影响的页面允许强制重新获取，不再被相同 `touched` 的提前返回拦住。
- 正常更新只在用户点击后运行，沿用独占数据操作门闩、取消及并发限制；Search/Viewer 不等待全库索引构建。
- 收藏不因远端删除而自动移除；改名后保留旧收藏及有效远端 Redirect，没有 Redirect 时按现有 not-found 行为处理，不擅自迁移用户收藏。
- 当前格式 2 / 加工版本 2 的页面表及索引继续兼容；同步状态以可选元数据扩展，不提高格式或加工版本。无同步状态的当前库仍可正常离线使用；旧加工版本继续按现有校验拒绝，不能将“无同步状态兼容”误解为放宽内容校验。
- 导入成功后在 staging 安装前使同步状态失效，首次更新做目录核对；不得因 Manager 或保留辅助文件而跳过导入库缺少的数据。该修改需同步数据库交换契约与 ADR 0012 的补充说明。

## 方案与已选默认值

### 1. 同步状态随内容库保存

复用 `WikiDatabaseMetadata`，使用一个版本化 `sync_state` JSON 值，至少包含：状态版本、规范化 API 地址和命名空间集合、内容/加工版本、已成功覆盖的远端 UTC 时间、对应锚点事件 ID 及时间、最近完整核对时间、是否有未完成同步。可选元数据无效时只禁用快速同步，不阻止离线启动；现有内容格式/身份校验仍先执行。

`WikiBook.UpdateTime` 继续用于展示，不作为游标。首次下载、旧版代码下载留下的库、导入库和配置身份变化均走完整核对建立基线。更新开始前持久化未完成标记；所有页面、Redirect 和所需资源成功后才一次性推进时间及锚点、清除标记。崩溃或取消后下次显式更新执行完整核对，并重新检查媒体，保证资源任务不会因页面已提交而丢失。

完整核对的游标必须从核对开始前取得的服务器时间建立，并补读核对期间的事件；没有补读时只保存开始时间，不能把结束时间当作已覆盖进度。页面解析期间再次发生变化时，不得把下载前旧 HTML 标记为下载后的新 `touched`；对不稳定页面保留重试状态。

### 2. 快速发现变化

使用现有 HTTP transport 访问 `action=query&list=recentchanges`，请求 `title|ids|timestamp|loginfo` 等必要字段，处理原始 continuation，不用 `rctoponly` 丢弃中间移动/删除信息。不把读取限制为正文命名空间，以便识别模板、文件及其他嵌入源变化。

每轮使用服务器时间固定上界；下界从成功时间回退 5 分钟，按事件 ID 去重。同页多次事件只形成一个最终处理目标，但移动涉及的旧/新标题全部保留。再次查询候选当前的 page ID、title、namespace、redirect、missing、touched，按当前状态执行，不直接照历史删除日志删数据。

锚点验证与增量时间窗口分开：以保存的事件 ID 和时间进行有界验证；无新事件时可保留旧锚点并推进已覆盖时间，不要求旧锚点仍落在新的 5 分钟窗口内。无可验证锚点、锚点已被清理、API 警告/隐藏信息使覆盖不可信、未知内容类日志、无法解释的移动或不支持必需接口时转完整核对。不硬编码“日志保存 30 天”；短暂网络/限流错误沿用有界重试，仍失败则结束本轮，不以全量请求放大故障。重叠事件去重后，普通候选须再次比较轻量元数据，跳过已同步页面；依赖强制刷新单独标记。

### 3. 页面、Redirect、删除和移动

- 新建/编辑：只解析最终候选，复用现有处理器及页面事务。页面元数据一律来自远端，不写本机时间冒充远端版本。
- Redirect：刷新候选旧/新标题及必要来源的当前映射；从正文变 Redirect 时移除旧正文及索引，从 Redirect 变正文时移除旧映射。
- 删除：必须有成功的当前查询明确返回 missing；403、404 网关页面、超时、非 JSON、空列表和权限错误都不是删除依据。
- 移动：先成功保存新目标，再协调处理旧标题；保留服务器当前真实存在的 Redirect，不伪造永久映射。中途失败保留未完成标记，下轮修复。
- 完整核对先完整取得所有目标命名空间的页面及 Redirect 清单，再与本地轻量元数据批量比较。对缺失项逐批复核当前状态后才删除，抓取未完成时禁止差集删除。

### 4. 模板与资源依赖

对变化的可嵌入页面，通过 `embeddedin` 获取受影响页面并进行有去重的递归展开；文件事件使用 `imageusage` 查引用方。只下载配置命名空间内的页面，但遍历过程中允许经过模板/模块等中间依赖；移动/删除需同时检查旧、新标题的依赖。

依赖展开默认最多 100 次分页请求或 10000 个候选，达到任一上限转完整核对，不能截断后宣称成功。模块/扩展依赖无法由目标站点 API 完整表达时也转完整核对，并记录原因。站点兼容探测不通过的来源仅保留完整核对模式，不承诺快速路径。

普通变化资源沿用条件请求；明确收到文件上传/替换事件时，不只依赖原时间戳，重新获取该文件对应的已存媒体和相关页面所需资源。媒体失败保留未完成标记。文件删除只有远端文件 API 明确确认且本地键映射唯一时才删除对应媒体记录；不清理其他孤立资源。

轻量模式不新增媒体；现有完整版模式覆盖独立文件变化。无有效日志基线或恢复未完成更新时，遍历现存资源记录和当前页面提取出的 URL 做媒体核对，不能仅依赖可能失效的辅助文本清单。对已确认遗漏来源的媒体，允许在完整核对中重新获取相关页面重建 URL。

为覆盖异步模板失效、站点缓存和可见日志不能表达的变化，每 7 天在下一次用户点击更新时执行完整元数据核对及资源条件检查。明确只提供与站点最终可见状态一致的同步，不声称是远端原子快照或即时一致。

### 5. 接口与进度

保留 `WikiDataUseCases.UpdateAsync(bool includeResources, ...)` 和 HTTP transport 公共签名。在 Core 内增设范围有限的变化读取/候选归并实现，并给数据库增加轻量元数据批量查询和同步状态读写方法。

`WikiOperationSummary` 尾部增加具有默认值的 `Checked`、`Skipped`、`Deleted`、`UsedFullScan`；`Pages` 只统计实际成功替换，不把检查/跳过计为下载。增加变更发现、完整核对、删除等 `WikiProgress.Code`，Windows 仅更新既有进度和完成文案，显示实际下载、跳过、删除与失败数。无变化时 `Changed=false`，仍可推进成功覆盖时间。

### 6. 索引维护与搜索回归边界

复用当前 `OptimizeSearchIndexAsync(reclaimSpace: false)`，每轮页面/区域实际写入或删除后最多执行一次；纯检查、跳过、仅资源变化不得触发。增量和失败重试不调用 VACUUM，也不逐页 optimize；完整首次下载保留已有空间回收行为。维护失败时保留未完成状态，UI 如实报告页面已提交但本轮未完成。维护和事务取消均需等待底层 SQLite 操作结束再释放门闩。

同步实现不得修改现有搜索排序、按页合并、Alias 或加工器规则。新页面与更新页均经过当前加工版本 2；保留 `EvidenceRegions`、代表区域真实 Anchor 和 `data-wiki` 链接，不在同步过程中重新实现 HTML 加工。性能统计拆分变化发现、正文/媒体下载、逐页事务和索引维护，避免把 optimize 成本算成远端检查耗时。

## 验证与回归计划

- 请求级：10000 页、0 个新事件（重叠窗口允许旧事件）时无 `allpages`、全量 Redirect 或正文 parse；有 3 个直接变化页面且无依赖时只替换这 3 页，同页多次修改合并处理。与首次基线核对区别统计。
- 完整核对：当前加工版本 2 的库无状态、导入较旧快照、锚点过期、接口不支持、配置改变、7 天周期和未完成恢复均进入正确分支；使用标题/时间轻量查询，不读取全库 HTML。无新事件跨过多个 5 分钟窗口时不因旧锚点移出窗口而反复全量核对；初始核对期间的新事件不被结束时间跳过。
- 一致性：新增、编辑、删除后重建、连续改名、跨命名空间移动、正文/Redirect 相互转换、收藏保留，旧词从 FTS 消失、新词立即可查。
- 最新搜索回归：更新后“雪人”与“雪人炮”的标题候选顺序、每页一条且上限按页应用、同页 `EvidenceRegions` 完整、实体页内召回、多词匹配、字面 `%`/`_`/反斜杠、真实 Anchor 与站内链接保持有效。复用 `SearchQueryTests`、加工器及现有 Viewer 链接测试；不改 Viewer 时不重复运行历史 GUI smoke。
- 维护：无变化/仅资源时 optimize 和 VACUUM 调用为零；页面新增/更新/删除一轮最多一次 optimize、零 VACUUM。统计实际写入而非遍历数，覆盖维护失败及 SQLite 尚未结束时取消，不允许下一轮抢入。
- 依赖/媒体：模板和嵌套模板变化、模块能力不支持、依赖循环/上限、独立图片覆盖与删除、304、错误 Last-Modified、完整/轻量模式、导入后缺失 URL。
- 故障：列表截断、API error/warning、非 JSON、重复 continuation、事件乱序与重叠、失败页面、资源失败、删除事务失败、取消和进程中断；不得误删或推进未完成游标。
- 交换：带/不带同步状态的 v2 导入导出、导入失败回滚、导入后首次更新、旧版本忽略可选状态后再次使用新版；不复活退休格式。
- Windows：优先执行受影响的生命周期、搜索、数据库交换、Application 数据用例与 Windows 管理页 tests，再构建受影响的 Windows Release 入口验证集成。实际运行进度、取消与重试，并在副本更新后检查 Search/Viewer/收藏。当前不影响启动/打包链路，不默认重复全量 tests、publish 或 smoke；后续发现跨模块风险时说明补足覆盖后再扩大验证。UI 仅文案变化不触发 terraria-ui；若需要新增控件或布局则先使用该 Skill。
- 真实性能：在相同库副本、相近网络条件记录旧完整检查与新版的请求数量、字节、检测/下载/总耗时。普通少量变化场景以检查请求减少至少 80% 为目标；耗时报告实测值，不承诺固定秒数。实际线上无编辑样本时以离线 fixture 证明分支，不能冒充真实更新验收。

## 风险与回退

主要风险是日志并不等于全部渲染变化、同步时间早于内容完成、导入后状态串用、错误判定删除、媒体更新遗漏。上述依赖展开、周期核对、未完成标记、导入失效及远端确认分别约束这些风险。

默认原子性为逐页而非整站；取消后已提交内容保留，下次可重复执行。事务取消须等待底层事务实际结束再释放操作门闩，不能只取消 await 后启动另一轮数据库操作。

源码回退到实施前保存点时仍可读取 v2 页面和索引；回退前将同步元数据标记失效，后续新版首次更新全量核对。真实验收使用副本并保留原库快照；页面删除回退需要恢复快照，不能声称 Git 能恢复用户数据。
