# 问题驱动检索关键词探索

## 1. 调查结论

本次使用现有 `WikiToolTestHost --snapshot` 启动本地 Wiki Tool，通过 MCP 直接调用且仅调用 `search_wiki` 与 `read_wiki`；没有调用 Python Agent、DeepSeek 或其他模型 API，也没有直接查询 SQLite、扫描全库或运行问答验收。

调查按小批次覆盖了合成与制作链、敌怪/Boss 掉落与宝藏袋、Boss/事件召唤与结束、环境与探索、装备属性与套装、药水增益/减益、NPC 入住/出售/快乐度、钓鱼、宝箱和种植。实际共执行 64 次 Search、41 次 Read；其中包含 7 次用章节显示名直接拼接 anchor 的失败读取，以及随后用 Search 返回的原样编码 anchor 成功读取的复验。查询固定使用 `max_results=5`，未使用 AI 默认省略数量的设置路径。

主要结论：

- 在沿用现有实体识别能力后，只加一个与问题对应的主题词，通常比把自然问题整句或多个主题词堆入 query 更容易解释。别名解析不是本次关键词收益判断的变量，已从关键词结论和重复验证中排除。
- 已验证有检索/导航价值的标准词包括：`制作`、`配方`、`制作树`、`制作站`、`掉落`、`宝藏袋`、`召唤`、`召唤和生成`、`生成条件`、`套装`、`功能`、`增益药水`、`增益`、`减益`、`持续时间`、`入住`、`出售物品`、`快乐`、`生活偏好`、`生物群系`、`地层`、`钓鱼`、`渔获`、`宝匣`、`机制`、`种植盆`。
- “宝藏袋”是规范页面名；Boss 的袋子内容集中在“宝藏袋 > 类型”，并可由 Search 导航提供 Boss 专用 anchor。完整掉落不能由一次章节读取或目录本身证明。
- “制作树”不是“制作术”的同义词。它既可命中专门页（如“天顶剑/制作树”），也出现在“天顶剑 > 制作 > 制作树”；直接配方仍应优先使用“配方”。
- `植物种植`基线搜索为空；`种植`会解析到“种植盆”，其正文说明种子、生长和收获。因此植物问题应先用具体实体（例如“种植盆”或具体植物/种子名），不要把“植物种植”当固定标准词。
- `NPC` 的章节名是“快乐”，个人 NPC 页常用“出售物品”“生活偏好”，入住条件多在页面导语/正文而非名为“入住”的独立章节；“幸福度”没有显示出比“快乐”更好的导航效果。
- 章节显示文字不一定是可用 anchor。实测 `宝藏袋#类型`、`天顶剑#配方` 等直接使用显示名会返回 `anchor_found=false`；使用 Search 返回的原样编码 anchor 可成功定向读取。这是 Search/Read anchor 兼容边界，不是关键词召回失败。

局限：样本是代表性问题和少量实体，不是用户频率统计；没有真实模型对照实验，因此不能宣称回答成功率、质量或 Token 消耗已经改善。长页（例如“宝藏袋”“钓鱼”）的单次 Read 可能返回 continuation，调查只读取了判断关键词和章节组织所需的范围。

- Terraria 事实问题仍必须先调用 search_wiki，再调用 read_wiki；关键词表只辅助召回和导航，不是事实证据。保留用户的自然问法，沿用现有实体/别名解析；本指南只决定主题词，不把别名解析当作关键词优化。不要把整行关键词全部拼入一次搜索。

## 4. 待确认和未解决事项

- **本地工具查询已验证有效**：`宝藏袋`、`制作树`、`配方`、`召唤和生成`、`套装`、`功能`、`快乐`、`生活偏好`、`生物群系`、`地层`、`机制`、`种植盆`等页面或章节定位规则；Search 返回 anchor 原样复用后可以成功定向 Read。实体/别名解析只作为固定查询实体的既有前置，不是本次关键词结论。
- **有本地用词依据，但检索收益尚未充分验证**：`天气`、`世界状态`、`效果`作为跨页面通用 query 词；`入住`作为个人 NPC 页导语中的意图词；不同版本/难度词与上述主题词的最佳组合。当前只保留已有页面/章节事实，不把它们写成强制规则。
- **工具/结构问题而非关键词问题**：章节显示名与实际 anchor 可能不一致；本次已观察到 7 次 raw display anchor 失败，现有建议是只使用工具返回的 anchor，不在本次实施修复工具兼容性。
- **待确认**：用户此前的“保灶带”与“制作术”没有本地结果，虽然“宝藏袋”“制作树”分别可命中，不能据此确认原意；“药些探索”无结果且含义不明确，保留待用户澄清。
- 本次没有用户查询日志，也没有真实模型 API 对照，因此不得将“高频重要”解释为统计频率，不得声称回答质量、成功率或 Token 消耗已经改善。
