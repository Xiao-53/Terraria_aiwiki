## 原真实对照方案（已被用户收窄）

原计划要求用户自行执行或另行授权付费对照。2026-09-11 用户明确授权真实调用，随后明确“只测试优化后的，测试两个五轮会话，旧的不用”。因此本轮不执行旧版、每题3次重复或统计前后下降幅度，不能据此证明 Token 下降或质量相对旧版不退化。

执行时固定 provider、模型、思考强度、配置、同一本地数据快照、同一问题及完全相同的最近4轮历史；在基线提交和本分支分别运行，每题至少3次。题集覆盖上表，并在真实数据中加入简单属性、跨页比较、跨版本冲突、仅部分支持和不存在证据问题。真实问题的预期事实必须先由同一快照人工核对，不能用模型自己的答案评分。

各轮只记录脱敏 scenario ID、提交、状态、请求/工具次数、input/cached input/output/total、延迟、应支持事实总数/正确数、列表应列/实际正确/遗漏数、无依据结论数、错误版本数、误拒答。provider 未提供 cached 或费用字段时标为不可用，不用字符除法或推算账单补全。原始问答和资料不进入生产日志或提交。

原对照目标为总体真实 input 下降、事实正确率和覆盖不退化，并报告波动及延迟。该目标本轮不作结论；仅完成用户最新指定的新版两个五轮运行、绝对用量与事实/来源验收。

### 验收脚本故障与费用披露

首次运行的10次提问，以及随后1次定位请求，在测试统计包装器中把SDK的`response.usage`属性误写为`response.usage()`，响应结束后抛TypeError，被Agent归一为unknown，尚未进入工具执行和有效会话历史。11次启动/诊断请求可能已计费，但usage未保存，**不计入上面的209016 Token，也不得记作0 Token/0费用**。这些预热请求也可能影响随后缓存命中；本轮没有对照实验，不把缓存当优化归因。

已修复仅测试脚本，并增加遇到首次失败即停止、两协议离线包装器回归。离线完整Search→Read→Answer通过后，才完成上面的两个有效五轮会话；没有再次执行旧版本。最终原始合成问答保留在本地忽略的测试artifact供人工核对，不进入Git；本文件只提交数值和人工评分。
