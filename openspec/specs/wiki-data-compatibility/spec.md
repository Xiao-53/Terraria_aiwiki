# Wiki 数据与数据包兼容契约

- 状态：confirmed baseline
- 适用范围：Portable Wiki Core、数据迁移、导入导出、Windows 与未来 Android
- 来源：现有 Terraria Wiki Offline P0 行为；Master Architecture v0.6

## 目的

确保客户端宿主、Presentation 或物理 project 结构变化时，现有 Wiki 数据库、数据目录和数据包仍是同一份可持续使用的数据资产。

## 契约

### 数据库兼容

- 现有 Manager/Content 数据库及其表、字段、索引、FTS5 数据和业务语义属于 P0。
- 新 Core 必须能读取代表性旧数据库；需要写入、建表、种子或迁移的流程必须在可恢复副本上独立验证。
- “成功打开旧库”与“成功执行迁移/初始化”是两个不同验收项，不得用读写初始化代替只读兼容检查。
- 搜索修复可以改变已确认的问题行为，但必须通过独立 Phase 和回归证据，不得借物理迁移静默改变查询语义。

### 数据包兼容

- 当前源码使用 `WIKIDATA` 包格式和 `.pkg` 扩展名；旧仓库 README 中的 `.pak` 是待样本确认的历史兼容事实。
- 扩展名不是格式兼容的唯一判据。兼容验证必须检查 header、metadata、文件清单、长度、内容 hash 和目标数据语义。
- 新导出包不得只由同一套新导入代码自证兼容；必须使用 golden fixture 与独立兼容 oracle。
- 改变包字节格式、字段语义或旧版本迁移规则，需要独立决策、迁移方案和回退，不得作为 UI 迁移附带变更。

### 安全导入

- 包内相对路径规范化后必须保持在指定临时根目录内；绝对路径、路径穿越、空路径和重复冲突路径必须拒绝。
- metadata 长度、文件数量、单文件大小、累计大小和剩余字节必须做边界检查，不得信任包内声明。
- 导入必须先在临时目录完整解析和验证，再替换目标数据；失败时不得留下部分生产数据。
- 用户生产数据库和数据包原件不得作为 PoC 输出目标；真实样本使用前后必须有可核对的 hash 和恢复方式。

### 单一事实源

- 手动搜索、离线阅读和 AI 必须复用同一份本地 Wiki 数据。
- 不建立供 AI 单独使用的第二套 Wiki 数据库、向量库或预生成知识副本。

## 验收场景

1. 代表性旧数据库以只读方式检查，文件 hash 不变。
2. 同一数据库副本执行新 Core 初始化/迁移后，P0 表和代表性数据语义保持兼容。
3. golden 旧包由独立 oracle 解析，新导出包通过相同 oracle。
4. 路径穿越、绝对路径、异常长度、重复路径和截断包被安全拒绝，临时根目录之外无写入。
5. 导入失败后原目标数据仍可恢复并继续打开。

## 变更规则

本契约变化时更新本 spec；具体 SQL、fixture、checker 实现与平台命令写入对应 Phase 计划。
